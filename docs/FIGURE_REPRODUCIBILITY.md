## Manually Curated Architecture Figure

`assets/nonicu_table_lineage_construction.svg` is a manually curated source-table-to-analysis-dataset lineage figure used in the Quarto report. It is not generated by an analysis notebook and contains no patient-level data. It documents table provenance and the analysis workflow, and should be refreshed manually if the SQL table structure or report architecture changes.

## Refresh Workflow

1. Run the relevant notebook from the repository root or from the `notebooks/` directory.
2. The notebook resolves the project root, creates `assets/` if needed, and saves the figure using the stable filename above.
3. For the manually curated lineage SVG, update the source figure outside the public repository and copy the refreshed SVG to `assets/nonicu_table_lineage_construction.svg`.
4. Run `quarto render reports/nonicu_raas_mortality_report.qmd`. The post-render helper copies each referenced canonical image into `docs/assets/` for GitHub Pages and rejects missing images or broken relative resources. Commit both the canonical images and synchronized public copies with the rendered HTML.
5. After Pages deployment, run `scripts/check_public_report.py` to verify the live HTML and referenced images/links return HTTP 200. A successful Pages build alone does not prove the image URLs work.

## Data Protection

The figure files contain only aggregate, presentation-level summaries. No patient-level records, local analysis extracts, credentials or protected health information are stored in `assets/`.

## Interpretation Boundary

The README figures summarize observational associations based on documented inpatient prescription exposure. They do not confirm medication administration and should not be interpreted as causal treatment-effect evidence. Residual confounding may remain despite multivariable adjustment and sensitivity analyses. Current Python execution evidence is described in [reproducible scope](REPRODUCIBLE_SCOPE.md).


The additional notebook 04c exports `assets/prediction_time_calibration.png` from aggregate time-specific holdout bins. The Quarto post-render step synchronizes it to `docs/assets/`. It displays separate ward-confirmed admission/24h populations with held-out-patient intervals conditional on fitted models; see [prediction validation](PREDICTION_TIME_VALIDATION.md).
